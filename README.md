# OTUS React homework

Учебный проект курса React.js Developer. Приложение опубликовано на GitHub Pages; компоненты также доступны в локальном Storybook.

## Команды

```bash
npm install
npm start
npm run typecheck
npm test
npm run build
npm run deploy
npm run storybook
npm run build-storybook
```

После запуска приложение доступно по адресу `http://localhost:2233`, а Storybook — по адресу `http://localhost:6006`. Опубликованное приложение находится на <https://serega7570.github.io/otus_homework/>. `npm run deploy` и workflow GitHub Actions публикуют каталог `dist` в ветку `gh-pages`.

## Домашнее задание 5: состояние приложения

- `ModalWithInput`: управляемый инпут над кнопкой; введённый текст отображается в модальном окне. Закрытие окна сохраняет текст.
- `ThemeProvider`: React-контекст хранит светлую или тёмную тему, CSS-переменные меняют оформление всех вложенных компонентов. `ThemeSwitcher` находится в Header.
- `LanguageProvider`: React-контекст хранит язык (`ru` / `en`), а `I18nextProvider` передаёт экземпляр i18next компонентам. `LanguageSwitcher` находится в Header. Переводятся интерфейсные тексты; пользовательский ввод и данные, переданные через props, сохраняются.

Оба провайдера подключены в `App` и глобальном декораторе Storybook. В приложении по умолчанию выбраны тёмная тема и русский язык, в Storybook — светлая тема и русский язык. Состояние хранится в памяти и сбрасывается при перезагрузке страницы.

Новые примеры в Storybook находятся в разделе **Управление состоянием**:

1. **ModalWithInput / Default** — введите текст, откройте и закройте окно.
2. **ThemeSwitcher / WithPreview** — переключите тему и откройте окно, чтобы проверить оформление.
3. **LanguageSwitcher / WithTranslatedComponent** — выберите English: подписи инпута, кнопки и модального окна изменятся.

Проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`. Интеграционные тесты проверяют передачу текста в окно, повторное открытие, смену темы и языка, сохранение ввода и независимость провайдеров.

## Домашнее задание 6: порталы и списки

- `OperationList` принимает массив операций из первого ДЗ и выводит существующие `OperationCard`. Для ключей используется `operation.id`; пустой массив показывает сообщение об отсутствии операций.
- `OperationFeed` хранит список в состоянии. По умолчанию показывает 6 операций и добавляет по 6 через кнопку **Показать ещё** или `IntersectionObserver` у конца списка. Используется `createRandomOperation` из `src/homeworks/ts1/3_write.ts`.
- Наблюдатель отключается при размонтировании и обновлении списка; повторные уведомления не добавляют одну и ту же порцию несколько раз. Генерация происходит вне функции обновления состояния, а существующие карточки оптимизированы через `React.memo`.
- Если `IntersectionObserver` недоступен, можно использовать кнопку. Для режима только с кнопкой передайте `autoLoad={false}`. `initialCount` задаёт начальное количество при монтировании, `batchSize` — размер добавляемой порции.
- `Modal` использует `createPortal` в `document.body`: при открытии появляется маска с окном, при закрытии или размонтировании она удаляется. Тема и язык сохраняются через контекст и атрибуты на корне портала.

В приложении список находится в разделе **Доходы и расходы**. Кнопка размещена над списком, чтобы автоматическое добавление элементов не сдвигало её при прокрутке. В Storybook добавлены **OperationList / Default**, **OperationList / Empty**, **OperationFeed / ShowMoreButton** и **OperationFeed / InfiniteScroll**. Примеры модального окна из предыдущего ДЗ теперь используют портал; **ModalWithInput / InsideClippedContainer** демонстрирует окно за границами обрезающего контейнера.

Тесты проверяют данные и стабильность элементов списка, добавление порций из генератора, автозагрузку, повторные и устаревшие уведомления наблюдателя, работу без IntersectionObserver, а также монтирование и удаление портала с сохранением темы и языка.

## Домашнее задание 8: сложный компонент

Реализован `CroppedText` из [учебного списка компонентов OTUS](https://github.com/React-js-OTUS/spirit-drive.github.io/blob/master/src/components/CroppedText/CroppedText.stories.tsx). Компонент принимает строку через `children`, число строк `rows` (по умолчанию 3), флаг раскрытия `opened` и необязательный `className`.

- `useLayoutEffect` измеряет текст до первого отображения. Бинарный поиск подбирает максимальный префикс с многоточием, который помещается в заданное число строк.
- `ResizeObserver` следит за шириной самого компонента: пересчёт работает при изменении контейнера независимо от размера окна. Уведомления объединяются через `requestAnimationFrame`; изменения только высоты игнорируются, чтобы избежать циклов измерения.
- При изменении текста, числа строк или загрузке шрифтов измерения повторяются. Наблюдатель, обработчики и ожидающий кадр очищаются при размонтировании. Если ResizeObserver отсутствует, используется событие `resize` окна.
- Раскрытие управляется родителем. Короткий текст остаётся целым; пустой текст, нулевая ширина и `rows={0}` обработаны. Эмодзи и составные символы не разрываются; скринридерам всегда доступен полный текст.

В приложении компонент используется в разделе **Заметки об обучении**, с переводом и кнопкой раскрытия. В Storybook раздел **Сложные компоненты / CroppedText** содержит регулятор ширины, кнопку раскрытия и восемь сценариев: изменение размеров, одна строка, раскрытый, короткий и пустой текст, длинные слова с эмодзи, переносы строк и нулевое число строк. Через Controls можно менять текст и число строк.

Тесты проверяют бинарный поиск, целостность символов, пересчёт по ResizeObserver, объединение уведомлений, изменение props, восстановление после нулевой ширины, очистку и работу без наблюдателя. Для проверки реальных размеров также используется браузерный прогон собранного Storybook.

## Домашнее задание 10: AccountService через TDD

`AccountService` управляет скидками для четырёх типов пользователей (`Standard`, `Premium`, `Gold`, `Free`) и трёх типов товаров (`Car`, `Toy`, `Food`). Конкретные значения не зашиты в типы пользователей: они задаются через сервис и сохраняются в хранилище.

### Контракт и правила

| Метод | Назначение |
| --- | --- |
| `getUserDiscount(userType)` | Прочитать общую скидку типа пользователя. |
| `setUserDiscount(userType, discount)` | Записать или заменить общую скидку. |
| `getProductDiscount(userType, productType)` | Прочитать скидку для пары пользователя и товара. |
| `setProductDiscount(userType, productType, discount)` | Записать или заменить товарную скидку. |
| `calculateDiscount(userType, productType)` | Сложить общую и товарную скидки. |

Все методы асинхронные. Скидки измеряются в процентах; отдельное значение — конечное число от 0 до 100, включая дробные значения. Отсутствующая запись (`undefined`) означает 0; запись 0 сбрасывает скидку. Итог — именно сумма: 10 + 5 = 15, а 80 + 70 = 150. Ограничение итоговой суммы в задании не указано, поэтому расчёт не обрезает её до 100. Сервис рассчитывает скидку, а не цену товара.

Неизвестные типы и некорректные проценты отклоняются через `RangeError` до записи в хранилище. Прочитанные значения также проверяются; ошибка базы не заменяется нулевой скидкой, а передаётся вызывающему коду.

`DiscountRepository` описывает чтение/запись двух видов скидок и передаётся в конструктор. `InMemoryDiscountRepository` реализует этот контракт через отдельные Map для общих и товарных политик. Сервис не зависит от React и реализации базы. Два сервиса могут использовать одно хранилище; разные хранилища изолированы. Для учебного приложения данные хранятся в памяти до перезагрузки страницы — подключение серверной базы не требуется.

Спецификация покрывает все 12 сочетаний типов, отсутствующие и нулевые скидки, сложение, дробные значения, границы, обновление и сброс, независимость записей, некорректные данные и ошибки чтения/записи. Unit-тесты используют моки `DiscountRepository`; интеграционные тесты проверяют реальное взаимодействие сервиса с базой в памяти.

На время операции элементы заблокированы; при ошибке чтения доступна повторная загрузка, ошибка записи сохраняет прежний результат. Запоздавшие ответы предыдущего сервиса игнорируются. Поддерживаются обе темы и оба языка.

В Storybook добавлен раздел **Сервисы / AccountService**: **EmptyPolicies**, **ConfiguredPolicies** (например, Gold / Car = 10 + 5) и **StorageUnavailable**. У каждого примера своё хранилище. ## Домашнее задание 11: роутинг

Приложение учёта операций использует `react-router-dom` и вложенные маршруты. Общий `AppLayout` содержит Header с `NavLink`, переключателями темы и языка и областью `Outlet`. Навигация доступна на всех экранах, включая мобильные размеры; текущий экран выделяется через `aria-current="page"`.

| Маршрут | Экран |
| --- | --- |
| `/` | Обзор проекта и демонстрации модального окна / CroppedText. |
| `/profile` | Существующая форма профиля с начальными значениями, валидацией, выводом в консоль и очисткой. |
| `/operations` | Список операций, автоподгрузка через IntersectionObserver и кнопка «Показать ещё». |
| `/operations/new` | Список и модальное окно создания операции. |
| `/operations/:id/edit` | Список и модальное окно редактирования выбранной операции. |
| `/forms` | Формы из предыдущего ДЗ, включая вход / регистрацию. |
| `/discounts` | Управление скидками через AccountService. |
| Любой неизвестный путь | Экран «Страница не найдена» с рабочей навигацией. |

Открытие окна определяется маршрутом, без дополнительного состояния `isOpen`: вложенный маршрут монтирует `OperationModal`, а `Modal` выводит портал в `body`. Закрытие крестиком или Escape удаляет портал. После перехода из списка закрытие возвращает назад по истории; при открытии прямой ссылки или обновлении страницы — заменяет URL на `/operations`. Кнопки браузера «назад» / «вперёд» также управляют окном. При неизвестном ID отображается сообщение без формы. Модальное окно удерживает клавиатурный фокус, восстанавливает его при закрытии и блокирует прокрутку страницы; длинная форма прокручивается внутри окна.

Форма использует прежнюю валидацию. Создание добавляет операцию в начало списка, редактирование заменяет её с сохранением ID; отмена не изменяет список. `OperationsProvider` сохраняет данные при переходах между экранами. Как и в предыдущих заданиях, данные хранятся в памяти: после перезагрузки пользовательские изменения и случайно загруженные операции сбрасываются. У демонстрационных операций стабильные ID, поэтому [прямая ссылка на редактирование](https://serega7570.github.io/otus_homework/#/operations/groceries/edit) работает после обновления страницы. Автоподгрузка при открытом окне приостанавливается.

Используется [HashRouter](https://reactrouter.com/6.30.6/router-components/hash-router), чтобы прямые ссылки и обновление страниц работали на статическом GitHub Pages без серверного fallback: например, [профиль](https://serega7570.github.io/otus_homework/#/profile) и [создание операции](https://serega7570.github.io/otus_homework/#/operations/new). Production-сборка загружает ресурсы с префиксом `/otus_homework/`. С этого ДЗ `npm run deploy` и `.github/workflows/deploy.yml` публикуют **приложение из `dist`**, а не Storybook. Storybook остаётся доступен локально; команда публикации Storybook в тот же адрес удалена.

Экран корзины по условию нужен интернет-магазину. Здесь выбран проект учёта операций, поэтому корзина не применяется; товарные компоненты из ранних упражнений остаются в Storybook.

В Storybook добавлены **Роутинг / Приложение**: Profile, Operations, CreateOperation и EditOperation. Они используют MemoryRouter и позволяют проверять переходы без изменения URL Storybook.

Интеграционные тесты проверяют переходы и активные ссылки, прямое открытие профиля и модальных окон, валидацию, создание и редактирование, сохранение списка между экранами, отмену, историю, Escape, удаление портала, темы / переводы, неизвестный ID и неизвестный URL. Проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`, а также браузерные проверки собранного приложения.
