# OTUS React homework

Учебный проект курса React.js Developer. Компоненты интерфейса собраны и опубликованы в Storybook.

## Команды

```bash
npm install
npm start
npm run typecheck
npm test
npm run build
npm run deploy
npm run storybook
npm run build-storybook
npm run deploy-storybook
```

После запуска приложение доступно по адресу `http://localhost:2233`, а Storybook — по адресу `http://localhost:6006`. Опубликованный Storybook находится на <https://serega7570.github.io/otus_homework/>.

## Домашнее задание 5: состояние приложения

- `ModalWithInput`: управляемый инпут над кнопкой; введённый текст отображается в модальном окне. Закрытие окна сохраняет текст.
- `ThemeProvider`: React-контекст хранит светлую или тёмную тему, CSS-переменные меняют оформление всех вложенных компонентов. `ThemeSwitcher` находится в Header.
- `LanguageProvider`: React-контекст хранит язык (`ru` / `en`), а `I18nextProvider` передаёт экземпляр i18next компонентам. `LanguageSwitcher` находится в Header. Переводятся интерфейсные тексты; пользовательский ввод и данные, переданные через props, сохраняются.

Оба провайдера подключены в `App` и глобальном декораторе Storybook. В приложении по умолчанию выбраны тёмная тема и русский язык, в Storybook — светлая тема и русский язык. Состояние хранится в памяти и сбрасывается при перезагрузке страницы.

Новые примеры в Storybook находятся в разделе **Управление состоянием**:

1. **ModalWithInput / Default** — введите текст, откройте и закройте окно.
2. **ThemeSwitcher / WithPreview** — переключите тему и откройте окно, чтобы проверить оформление.
3. **LanguageSwitcher / WithTranslatedComponent** — выберите English: подписи инпута, кнопки и модального окна изменятся.

Проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`. Интеграционные тесты проверяют передачу текста в окно, повторное открытие, смену темы и языка, сохранение ввода и независимость провайдеров.

## Домашнее задание 6: порталы и списки

- `OperationList` принимает массив операций из первого ДЗ и выводит существующие `OperationCard`. Для ключей используется `operation.id`; пустой массив показывает сообщение об отсутствии операций.
- `OperationFeed` хранит список в состоянии. По умолчанию показывает 6 операций и добавляет по 6 через кнопку **Показать ещё** или `IntersectionObserver` у конца списка. Используется `createRandomOperation` из `src/homeworks/ts1/3_write.ts`.
- Наблюдатель отключается при размонтировании и обновлении списка; повторные уведомления не добавляют одну и ту же порцию несколько раз. Генерация происходит вне функции обновления состояния, а существующие карточки оптимизированы через `React.memo`.
- Если `IntersectionObserver` недоступен, можно использовать кнопку. Для режима только с кнопкой передайте `autoLoad={false}`. `initialCount` задаёт начальное количество при монтировании, `batchSize` — размер добавляемой порции.
- `Modal` использует `createPortal` в `document.body`: при открытии появляется маска с окном, при закрытии или размонтировании она удаляется. Тема и язык сохраняются через контекст и атрибуты на корне портала.

В приложении список находится в разделе **Доходы и расходы**. Кнопка размещена над списком, чтобы автоматическое добавление элементов не сдвигало её при прокрутке. В Storybook добавлены **OperationList / Default**, **OperationList / Empty**, **OperationFeed / ShowMoreButton** и **OperationFeed / InfiniteScroll**. Примеры модального окна из предыдущего ДЗ теперь используют портал; **ModalWithInput / InsideClippedContainer** демонстрирует окно за границами обрезающего контейнера.

Тесты проверяют данные и стабильность элементов списка, добавление порций из генератора, автозагрузку, повторные и устаревшие уведомления наблюдателя, работу без IntersectionObserver, а также монтирование и удаление портала с сохранением темы и языка.

## Домашнее задание 7: паттерны React

Отрефакторены пять компонентов текущего проекта. Их прежние публичные props и оформление сохранены.

| Компонент | Паттерн | Изменение |
| --- | --- | --- |
| `ModalWithInput` | Container / Presentational, Controlled Component, Custom Hook | Контейнер хранит текст и управляет окном через `useDisclosure`; `ModalWithInputView` получает значения и обработчики от родителя. Хук также используется в прежних историях Modal. |
| `OperationFeed` | Container / Presentational, Custom Hooks, Render Props | `useOperationFeed` управляет операциями, `useIntersectionLoadMore` — наблюдателем с очисткой; `OperationFeedView` отвечает за отображение. Необязательный `renderOperations` позволяет заменить карточки без копирования загрузки. |
| `ProductCard` | Composition, Slots | Общие название, описание, цена и действия собраны в `ProductContent`. Карточка добавляет изображение и бейдж; действия передаются через `children`. |
| `ProductDetails` | Composition, Slots | Использует тот же `ProductContent`, передаёт категорию через `beforeTitle` и сохраняет заголовок `h2` вместо `h3`. Разметка и форматирование цены больше не дублируются. |
| `LanguageProvider` | Provider / Consumer, Single Source of Truth | Язык берётся из i18next через `useSyncExternalStore`. Отдельный `useState` для языка удалён: контекст и переключатель синхронизируются и при прямом вызове `i18n.changeLanguage`. |

Значения контекстов языка и темы мемоизированы; обработчики переключения стабильны. Это предотвращает лишние перерисовки потребителей при обновлении родителя. Экземпляры i18next остаются независимыми для каждого дерева провайдеров.

Примеры: **ModalWithInput / Controlled** показывает управление из родителя, **OperationFeed / WithDetailsRenderer** выводит подробные операции через render prop. Остальные истории продолжают демонстрировать прежнее поведение.

Тесты проверяют управляемый интерфейс модального окна, альтернативный рендерер списка, сохранение данных и семантики товарных компонентов, синхронизацию языка с i18next и отсутствие лишних перерисовок контекстных потребителей. Проверки прежних ДЗ также продолжают выполняться.

## Домашнее задание 8: сложный компонент

Реализован `CroppedText` из [учебного списка компонентов OTUS](https://github.com/React-js-OTUS/spirit-drive.github.io/blob/master/src/components/CroppedText/CroppedText.stories.tsx). Компонент принимает строку через `children`, число строк `rows` (по умолчанию 3), флаг раскрытия `opened` и необязательный `className`.

- `useLayoutEffect` измеряет текст до первого отображения. Бинарный поиск подбирает максимальный префикс с многоточием, который помещается в заданное число строк.
- `ResizeObserver` следит за шириной самого компонента: пересчёт работает при изменении контейнера независимо от размера окна. Уведомления объединяются через `requestAnimationFrame`; изменения только высоты игнорируются, чтобы избежать циклов измерения.
- При изменении текста, числа строк или загрузке шрифтов измерения повторяются. Наблюдатель, обработчики и ожидающий кадр очищаются при размонтировании. Если ResizeObserver отсутствует, используется событие `resize` окна.
- Раскрытие управляется родителем. Короткий текст остаётся целым; пустой текст, нулевая ширина и `rows={0}` обработаны. Эмодзи и составные символы не разрываются; скринридерам всегда доступен полный текст.

В приложении компонент используется в разделе **Заметки об обучении**, с переводом и кнопкой раскрытия. В Storybook раздел **Сложные компоненты / CroppedText** содержит регулятор ширины, кнопку раскрытия и восемь сценариев: изменение размеров, одна строка, раскрытый, короткий и пустой текст, длинные слова с эмодзи, переносы строк и нулевое число строк. Через Controls можно менять текст и число строк.

Тесты проверяют бинарный поиск, целостность символов, пересчёт по ResizeObserver, объединение уведомлений, изменение props, восстановление после нулевой ширины, очистку и работу без наблюдателя. Для проверки реальных размеров также используется браузерный прогон собранного Storybook.

## Домашнее задание 9: формы

В приложение добавлен раздел **Формы** с редактированием профиля, добавлением/редактированием операции и переключением между входом и регистрацией. Все формы используют Formik и нативные HTML-поля. Согласно заданию, успешная отправка только выводит данные в `console.log` и очищает форму; запросов, создания аккаунта и сохранения операций в список пока нет. При ошибках данные сохраняются, отправка блокируется.

`ProfileForm` адаптирован из [учебного компонента](https://github.com/React-js-OTUS/react-tutorial/blob/main/client/src/features/forms/ProfileForm/ProfileForm.tsx). Перед переносом изучены `NameField`, `AboutField` и [контейнер ProfileCompletedForm](https://github.com/React-js-OTUS/react-tutorial/blob/main/client/src/pages/ProfileScreen/ProfileCompletedForm/ProfileCompletedForm.tsx). Сохранены поля `name` / `about`, передача `formManager` и композиция полей. Ant Design и Sass заменены общим `FormField` и CSS проекта. `ProfileEditor` подключает `useFormik` через общий `useConsoleForm`, задаёт валидацию и начальные значения; серверная мутация заменена выводом в консоль и очисткой.

- **Профиль:** имя после удаления пробелов по краям — 2–60 символов; описание необязательно, до 500 символов. Заполненные значения можно изменить; после отправки очищаются оба поля.
- **Операция:** название 2–100 символов, тип `Cost` / `Profit`, категория и существующая календарная дата обязательны. Сумма — от 0,01 до 1 000 000 000, максимум два десятичных знака; описание до 500 символов. В консоль передаются режим, числовая сумма, объект категории и дата ISO. В режиме редактирования форма тоже очищается, а не возвращается к исходным данным.
- **Вход и регистрация:** проверяются формат email и пароль длиной 8–128 символов; регистрация дополнительно требует букву, цифру и совпадение подтверждения. Пароль сохраняется без изменения, email очищается от пробелов по краям. Подтверждение служит только для проверки и не попадает в данные отправки. Смена режима очищает значения и ошибки.

Ошибки появляются после потери фокуса или отправки и связываются с полями через `aria-describedby` / `aria-invalid`. Подписи, ошибки и сообщения об отправке переведены на русский и английский; смена языка сохраняет введённые данные. `initialValues` обновляют профиль и операцию при изменении props или Controls Storybook.

В Storybook добавлены **Формы / ProfileForm** (Empty, Edit, Disabled), **Формы / OperationForm** (Create, Edit, Income) и **Формы / AuthForm** (Login, Registration, Disabled). Поля доступны для ввода непосредственно в примерах; начальные данные и режимы можно изменять через Controls.

Тесты проверяют ограничения, email/пароль/подтверждение, даты, точность суммы, блокирование отправки при ошибках, вывод данных и очистку (включая заполненные формы), обновление начальных данных, переключение режима и перевод ошибок. Команды проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`.
