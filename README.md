Учебный проект курса React.js Developer. Приложение опубликовано на GitHub Pages; компоненты также доступны в локальном Storybook.

## Домашнее задание 14: работа с сервером

Актуальная версия использует [боевой REST API OTUS](https://github.com/React-js-OTUS/otus-rest-server). Два варианта регистрации из ДЗ 13 сохранены; вход, профиль, операции, товары и заказы теперь работают с сервером через RTK Query. Разделы предыдущих ДЗ ниже описывают поведение соответствующих веток.

Экраны:

- `/#/signup` — регистрация нового аккаунта (Fetch или RTK Query). После регистрации перейдите по ссылке **Войти**.
- `/#/login` — настоящий `POST /signin`. Сервер проверяет email и пароль; ответ содержит токен. Приложение сохраняет только токен в localStorage, проверяет его через `GET /profile` и возвращает пользователя на запрошенный защищённый экран.
- `/#/profile` — загрузка профиля и сохранение имени через `PUT /profile`. Сервер принимает имя от 7 символов из a–z, а–я, цифр, `_` и `-` (без пробелов). Это требование показано под полем; ошибка сервера без `fieldName` также привязывается к имени. Поле «О себе» из учебных примеров в API отсутствует, поэтому рабочая форма его не отправляет.
- `/#/operations` — список операций, `POST /operations`, `PUT /operations/:id`. Формы открываются в портальном окне по URL `/#/operations/new` и `/#/operations/:id/edit`. Прямая ссылка редактирования загружает запись отдельно, даже если её нет на текущей странице списка. Передаются настоящий ID категории, числовая сумма и поле `date` в ISO; дата операции не подменяется `createdAt`.
- `/#/shop` — список товаров с добавлением и редактированием (`POST /products`, `PUT /products/:id`), корзина и заказы. Количество — целое число 1–999; `POST /orders` получает `{ products: [{ id, quantity }], status: 'pending_confirmation' }`. Корзина очищается только после успешного ответа, показывается номер заказа и обновляется история. Ошибка сохраняет корзину для повторной отправки. История запрашивается с фильтром текущего `userId` и доступна после обновления страницы.

В формах операций и товаров категории загружаются с сервера. Для нового аккаунта раскройте **Создать категорию**, введите название и сохраните. Созданная категория появится в селекторе; захардкоженные `food` / `tech` не отправляются. Список категорий также поддерживает дополнительные страницы.

Подгрузка операций и товаров использует `build.infiniteQuery`: страницы по 6 записей, сортировка `createdAt DESC`, данные и параметры страницы передаются в API через JSON-строки. `IntersectionObserver` загружает следующую страницу при прокрутке; кнопка **Показать ещё** доступна также без observer. Записи объединяются по ID, повторные уведомления не дублируют запросы. Серверный `pagination.total` останавливает загрузку. При ошибке следующей страницы уже загруженные записи остаются на экране; **Повторить** повторяет упавшую страницу.

Все защищённые запросы используют `Authorization: Bearer <token>`. У API нет ролей администратора: прежние фейковые токены, профиль и проверка email администратора удалены из приложения. Профиль считается загруженным только после ответа сервера. Ошибка `ERR_AUTH` (в том числе с HTTP 400) или HTTP 401 завершает сессию; временная ошибка сети сохраняет токен и позволяет повторить проверку. Синхронизация между вкладками сохранена. При смене аккаунта / выходе очищается кэш API и состояние приватных форм; запоздавший ответ старой сессии не может заменить профиль или завершить новую сессию.

Общий обработчик поддерживает ошибки полей и общие ошибки API, таймаут 15 секунд, сбой сети и некорректный ответ. Во время отправки формы блокируются. Ошибка сохранения оставляет введённые значения и окно открытым; успех обновляет списки через инвалидацию тегов. Пароль не сохраняется в Redux state, localStorage или консоль. Ответы авторизации сохраняются только как `{ token }`, серверный профиль с хешем пароля отбрасывается. Работают русский / английский языки, светлая / тёмная темы и мобильные экраны.

Проверка вручную:

1. Зарегистрируйте уникальный email, перейдите на вход. Проверьте неправильный пароль, затем войдите с правильным.
2. Измените имя на `student_otus`, сохраните и обновите страницу: имя останется. Введите имя с пробелом: ошибка сервера появится под полем.
3. Откройте операции, создайте категорию, добавьте операцию. Отредактируйте её, обновите прямую ссылку редактирования и проверьте дату.
4. Создайте больше 6 операций или товаров и прокрутите список: появятся записи следующей страницы. В Network видны GET с `pagination` и `sorting`; после последней страницы загрузка остановится.
5. На экране товаров добавьте товар, положите в корзину, измените количество и оформите заказ. Номер появится в истории и сохранится после обновления страницы.
6. При Offline ошибки не очищают данные формы / корзины. Верните сеть и повторите отправку. Выйдите в другой вкладке: приватные экраны будут закрыты.

Проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`. Тесты прежней фейковой авторизации заменены проверками настоящего HTTP-контракта. Покрыты авторизация, профиль, POST / PUT операций и товаров, категории, заказы, пагинация и повторные запросы, очистка кэша и гонки при смене сессии. Storybook **Роутинг / Приложение** теперь показывает публичные экраны и перенаправления гостей; после настоящего входа доступны приватные экраны. У каждого примера отдельный store без localStorage, прежние отдельные компоненты остаются в своих разделах.

## Домашнее задание 13: работа с сервером, основы

Экран регистрации: `/#/signup` (в меню **Регистрация**, также есть ссылка со страницы учебного входа).

Реализованы два отдельных функциональных компонента:

- `FetchSignup` отправляет `fetch` непосредственно из обработчика компонента. Состояния отправки, ошибки и успеха хранятся в React; запрос отменяется при размонтировании.
- `RtkQuerySignup` вызывает `useSignupMutation`. `signupApi` использует `createApi` / `fetchBaseQuery`, reducer и middleware подключены к существующему Redux store. Состояния запроса предоставляет RTK Query.

Обе формы используют общую разметку `SignupForm` и обработчик серверных ошибок `getSignupErrors`. В форме только email, пароль и отправка; `noValidate` отключает браузерную валидацию. Нет `required`, ограничений длины, регулярных выражений или проверки значений на фронтенде; даже пустые поля отправляются на сервер без преобразований.

Запрос: `POST https://19429ba06ff2.vps.myjino.ru/api/signup`, JSON `{ email, password, commandId: 'otus-serega7570' }`. Используется HTTPS того же боевого сервера, чтобы запросы работали со страницы GitHub Pages. Контракт: [документация API OTUS](https://github.com/React-js-OTUS/otus-rest-server#signup-post).

Ошибки читаются из `{ errors: [{ extensions: { code }, message, fieldName? }] }`. Неверный email, занятый email, обязательное поле и некорректный пароль показываются рядом с полем. Боевой сервер может не прислать `fieldName`: для ошибки email и обязательных полей учитывается текст Mongoose. Остальные сообщения показываются над кнопкой; stack и HTML не выводятся. Обработаны сетевой сбой, таймаут 15 секунд, HTTP-ошибки и некорректный ответ. Успех показывается только при получении непустого токена. Во время запроса поля и кнопка заблокированы; после ошибки возможна повторная отправка, после успеха пароль очищается. Формы независимы, поддерживают обе темы и языки.

Регистрация создаёт настоящий аккаунт на сервере. Существующий учебный вход из ДЗ 12 по-прежнему демонстрирует роли и маршруты локально; серверная регистрация не выполняет автоматический вход в эту демонстрационную сессию. RTK Query сохраняет из ответа только документированный token, без серверного профиля; пароль не сохраняется в Redux state, localStorage или консоль.

Проверка каждой формы:

1. Введите `invalid-email` и произвольный пароль, отправьте: в Network виден POST с ответом 400, под email появляется **Укажите корректный email**. Ошибка приходит с сервера.
2. Отправьте пустые поля: запрос также уходит на сервер и показывает его ошибки.
3. Зарегистрируйтесь с уникальным email и паролем от 8 символов: появится сообщение об успехе. Для второй формы используйте другой email.
4. Повторите регистрацию с уже зарегистрированным email: появится ошибка о существующем пользователе.
5. В DevTools включите Offline и отправьте форму: появится ошибка соединения. Верните сеть и повторите отправку.

Storybook: **Сервер / Регистрация** — Fetch, RTK Query и отдельные состояния ошибки email, сетевого сбоя, отправки и успеха. Первые два примера обращаются к настоящему API; остальные показывают состояния без запросов.

Автоматические проверки: `npm run typecheck`, `npm test -- --runInBand`, `npm run build`, `npm run build-storybook`. Тесты обеих реализаций используют реальные Fetch API Request/Response с замоканным транспортом и проверяют тело запроса без клиентской валидации, серверные ошибки, сетевой сбой и повторную попытку, таймаут, блокировку повторной отправки, успех и публичный маршрут.

Тесты проверяют данные и стабильность элементов списка, добавление порций из генератора, автозагрузку, повторные и устаревшие уведомления наблюдателя, работу без IntersectionObserver, а также монтирование и удаление портала с сохранением темы и языка.

## Домашнее задание 8: сложный компонент

Реализован `CroppedText` из [учебного списка компонентов OTUS](https://github.com/React-js-OTUS/spirit-drive.github.io/blob/master/src/components/CroppedText/CroppedText.stories.tsx). Компонент принимает строку через `children`, число строк `rows` (по умолчанию 3), флаг раскрытия `opened` и необязательный `className`.

- `useLayoutEffect` измеряет текст до первого отображения. Бинарный поиск подбирает максимальный префикс с многоточием, который помещается в заданное число строк.
- `ResizeObserver` следит за шириной самого компонента: пересчёт работает при изменении контейнера независимо от размера окна. Уведомления объединяются через `requestAnimationFrame`; изменения только высоты игнорируются, чтобы избежать циклов измерения.
- При изменении текста, числа строк или загрузке шрифтов измерения повторяются. Наблюдатель, обработчики и ожидающий кадр очищаются при размонтировании. Если ResizeObserver отсутствует, используется событие `resize` окна.
- Раскрытие управляется родителем. Короткий текст остаётся целым; пустой текст, нулевая ширина и `rows={0}` обработаны. Эмодзи и составные символы не разрываются; скринридерам всегда доступен полный текст.

В приложении компонент используется в разделе **Заметки об обучении**, с переводом и кнопкой раскрытия. В Storybook раздел **Сложные компоненты / CroppedText** содержит регулятор ширины, кнопку раскрытия и восемь сценариев: изменение размеров, одна строка, раскрытый, короткий и пустой текст, длинные слова с эмодзи, переносы строк и нулевое число строк. Через Controls можно менять текст и число строк.

Тесты проверяют бинарный поиск, целостность символов, пересчёт по ResizeObserver, объединение уведомлений, изменение props, восстановление после нулевой ширины, очистку и работу без наблюдателя. Для проверки реальных размеров также используется браузерный прогон собранного Storybook.

## Домашнее задание 9: формы

## Домашнее задание 10: AccountService через TDD

`AccountService` управляет скидками для четырёх типов пользователей (`Standard`, `Premium`, `Gold`, `Free`) и трёх типов товаров (`Car`, `Toy`, `Food`). Конкретные значения не зашиты в типы пользователей: они задаются через сервис и сохраняются в хранилище.

### Контракт и правила

| Метод | Назначение |
| --- | --- |
| `getUserDiscount(userType)` | Прочитать общую скидку типа пользователя. |
| `setUserDiscount(userType, discount)` | Записать или заменить общую скидку. |
| `getProductDiscount(userType, productType)` | Прочитать скидку для пары пользователя и товара. |
| `setProductDiscount(userType, productType, discount)` | Записать или заменить товарную скидку. |
| `calculateDiscount(userType, productType)` | Сложить общую и товарную скидки. |

Все методы асинхронные. Скидки измеряются в процентах; отдельное значение — конечное число от 0 до 100, включая дробные значения. Отсутствующая запись (`undefined`) означает 0; запись 0 сбрасывает скидку. Итог — именно сумма: 10 + 5 = 15, а 80 + 70 = 150. Ограничение итоговой суммы в задании не указано, поэтому расчёт не обрезает её до 100. Сервис рассчитывает скидку, а не цену товара.

Неизвестные типы и некорректные проценты отклоняются через `RangeError` до записи в хранилище. Прочитанные значения также проверяются; ошибка базы не заменяется нулевой скидкой, а передаётся вызывающему коду.

`DiscountRepository` описывает чтение/запись двух видов скидок и передаётся в конструктор. `InMemoryDiscountRepository` реализует этот контракт через отдельные Map для общих и товарных политик. Сервис не зависит от React и реализации базы. Два сервиса могут использовать одно хранилище; разные хранилища изолированы. Для учебного приложения данные хранятся в памяти до перезагрузки страницы — подключение серверной базы не требуется.

Спецификация покрывает все 12 сочетаний типов, отсутствующие и нулевые скидки, сложение, дробные значения, границы, обновление и сброс, независимость записей, некорректные данные и ошибки чтения/записи. В приложении раздел **Скидки пользователей** позволяет выбрать тип пользователя и товара, отдельно сохранить общую и товарную скидки и увидеть формулу итоговой скидки. Расчёт выполняет сервис. На время операции элементы заблокированы; при ошибке чтения доступна повторная загрузка, ошибка записи сохраняет прежний результат. Запоздавшие ответы предыдущего сервиса игнорируются. Поддерживаются обе темы и оба языка.

## Домашнее задание 12: Redux Toolkit и защищённые маршруты

Глобальное состояние приложения перенесено в Redux Toolkit. `StoreProvider` подключает React-Redux Provider в App, а компоненты используют типизированные `useAppDispatch` / `useAppSelector`.

| Состояние | Назначение |
| --- | --- |
| `auth.token` | Фейковый токен или `null`. |
| `auth.initialized` | Флаг завершённой инициализации; меняется на `true` один раз при запуске приложения. |
| `auth.profile` | Фейковый профиль с именем, описанием, email и ролью; отсутствует без токена. |
| `operations.items` | Общий список операций, включая добавленные, отредактированные и случайно загруженные записи. |

Прежний OperationsProvider удалён. Генерация случайных операций и ID происходит в thunk, а slices выполняют только изменения состояния. Список, кнопка «Показать ещё» и IntersectionObserver читают и обновляют Redux. Сохранение формы создания/редактирования также обновляет Redux; thunk повторно проверяет роль администратора. Профиль можно редактировать: данные сохраняются в store и доступны после переходов между экранами.

### Учебная авторизация

[Экран входа](https://serega7570.github.io/otus_homework/#/login) использует существующие AuthForm и валидацию email / пароля. Во входе допустима любая строка пароля от 8 до 128 символов:

- **`admin@example.com`** — администратор при входе.
- **Любой другой корректный email** — обычный пользователь.
- **Регистрация** — обычный пользователь, в том числе при указании `admin@example.com`; проверяется повтор пароля и наличие буквы / цифры.

После валидной отправки создаётся уникальный фейковый токен. Пароль не передаётся в Redux, токен и localStorage; подключённая к приложению форма выводит в консоль только email. Отдельные учебные истории AuthForm сохраняют контракт ДЗ 9. Старый путь `/forms` перенаправляет на `/login`; формы профиля и операций используются на своих экранах, а отдельные демонстрации остаются в Storybook.

Это фейковая авторизация без сервера: роль закодирована в демонстрационном токене и используется для проверки клиентских маршрутов. Она не заменяет серверную проверку прав.

### Инициализация и синхронизация вкладок

Токен сохраняется под ключом `otus-homework-token` в localStorage. `initializeApplication` читает его перед открытием маршрутов, создаёт фейковый профиль при наличии токена и устанавливает `initialized`. Повторные вызовы, в том числе эффекты React StrictMode, не запускают инициализацию заново. Одно действие slice одновременно обновляет токен и создаёт / очищает профиль.

`createListenerMiddleware` сохраняет токен при входе и удаляет ключ при выходе. Обработчик [storage](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event) синхронизирует изменение и удаление токена в других вкладках, включая `localStorage.clear()`. События sessionStorage и других ключей игнорируются. При получении события читается актуальное значение localStorage, поэтому запоздавшее событие не восстанавливает старую сессию. Полученные изменения не записываются обратно — обмен не создаёт цикл. Слушатель удаляется при размонтировании; при повторном подключении состояние сверяется с текущим токеном.

Сохраняется только токен. Профиль восстанавливается из фейковых данных при загрузке или смене токена; редактирование профиля и операций хранится в памяти вкладки. При повторном получении того же токена сохранённые в этой вкладке изменения профиля не сбрасываются. Работа без доступного localStorage сохраняет авторизацию в памяти.
